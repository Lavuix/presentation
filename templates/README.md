## Как выбрать

| Что на слайде | Макет |
|---|---|
| Цифры, которые надо запомнить | `metrics` |
| Динамика во времени, доли | `chart` |
| Много параметров у нескольких объектов | `table` |
| Этапы, которые идут один за другим | `process` |
| Работы, растянутые по месяцам | `timeline` |
| Два-три варианта, из которых выбираем | `compare` |
| Список возможностей продукта | `features` или `cards` |
| Просто перечисление | `bullets` |
| Скриншот интерфейса | `image` (рамка `laptop` / `phone`) или `split` |
| Один сценарий на телефоне и на компьютере | `devices` |
| Процесс с проверками и развилками | `flowchart` |
| Кто кому что отправляет и в каком порядке | `sequence` |
| Из чего собрана система и с чем интегрирована | `architecture` |
| Охват продукта одним экраном | `map` |
| Что сейчас в работе у команды | `board` |
| Выбор из многих вариантов по двум критериям | `matrix` |
| Где сценарий ломается для человека | `journey` |
| Вехи, которые уже пройдены | `milestones` |
| Много показателей на одном статусе | `dashboard` |
| Вывод и из чего он сложился | `takeaways` |
| Мысль, ради которой собрали встречу | `statement` |
| Слова реального человека | `quote` |

## Правила выбора

- **Два одинаковых макета подряд — переделать.** Если подряд идут три списка,
  один превращается в `cards`, другой — в `metrics` или `chart`.
- **Цифры не живут в списке.** Три числа в буллетах — это `metrics`.
- **Таблица — последнее средство.** Если сравниваются два-три варианта по трём
  критериям, это `compare`, а не таблица.
- **Схема — не украшение.** `flowchart`, `sequence`, `architecture`, `journey`
  ставятся только тогда, когда без связей смысл теряется. Если элементы
  не связаны, это `cards`; если связь одна и линейная — `process`.
- **Не влезает — режь на два слайда.** Ужимать кегль ниже минимума из
  `rules/brand.md` нельзя.

## Общее для всех сниппетов

Сниппеты предполагают, что в начале файла подключён пролог:

```js
const TN = require('./templates/_prelude');
const { C, T, MX, MT, MB, CW, W, H, px, pt } = TN;
const p = TN.newDeck({ title: 'Название', theme: 'brand' });
await TN.prepare();
```

Все 28 макетов собираются в любой теме — оформление задаёт тема, а не сниппет
(`themes/README.md`). Поэтому цвета в сниппетах берутся ролевыми токенами:
`C.bg` — фон, `C.ink` — текст, `C.accent` — акцент, `C.onAccent` — текст на
заливке акцентом. Литеральных `'#e11b11'` в сниппетах быть не должно.

Контентные макеты начинаются с `TN.header(...)` и заканчиваются `TN.footer(...)`.
Титул, разделитель, тезис и финал колонтитула не имеют.

Геометрия в сниппетах выверена — подставляй свой контент, координаты не трогай.
Если контента больше, чем предусмотрено ёмкостью, это сигнал резать контент,
а не уменьшать отступы.

## Вертикальная композиция

Высоты в макетах не зашиты: строка и карточка ровно такой высоты, какой требует
её содержимое, а свободное место уходит в зазоры и в оптический центр. За это
отвечают три примитива пролога — `TN.place()`, `TN.rows()` и `TN.boxH()`,
подробно в [rules/layout.md](../rules/layout.md).

Поэтому не надо «дотягивать» карточку до колонтитула: пустая нижняя треть внутри
карточки выглядит как ошибка вёрстки, а воздух вокруг компактного блока — как
решение.

## Откуда примеры берут код

`examples/themes/build.js` и `examples/tn-life-strategy/build.js` не копируют
сниппеты, а загружают их прямо из этих файлов (`templates/_snippets.js`). Значит,
превью в документации всегда показывают то, что здесь написано. В своей деке так
не делай: копируй нужные сниппеты в свой `build.js`, чтобы их было видно и можно
было править под конкретный слайд.
