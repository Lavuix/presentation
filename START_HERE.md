# START HERE

Ты собираешь презентацию ТЕХНОНИКОЛЬ / TN Life. Этот репозиторий — свод правил и
библиотека макетов. Готового сборщика здесь нет: **слайды пишешь ты**, по шаблонам
из `templates/`. Репозиторий отвечает за то, чтобы результат выглядел одинаково,
кто бы его ни собирал.

Результат — `.pptx` 16:9 (1920×1080), где текст, таблицы и диаграммы остаются
редактируемыми в PowerPoint. Никаких слайдов-картинок и никакой конвертации HTML.

---

## Порядок работы

### 1. Прочитай правила

Обязательно, до первой строки кода:

- `rules/layout.md` — сетка, координаты, поля, колонтитул. Здесь система координат,
  в которой написаны все шаблоны.
- `rules/brand.md` — цвета, типографика, иконки, логотипы.
- `rules/voice.md` — язык и тон текста на слайдах.

`rules/quality.md` понадобится на шаге 6 — это чек-лист приёмки.

### 2. Выбери тему

Тема задаёт цвета, шрифт и обложку; макеты и сетка у всех тем общие. Каталог —
`themes/README.md`, там таблица «когда какую брать».

| Тема | Когда |
|---|---|
| `brand` | дека от лица компании: стратегия, внешняя аудитория, итоги года |
| `division` | дека департамента или завода — та же брендовая, но обложка чистым цветом |
| `digital` | материалы TN Digital: гильдии, митапы, техрадар |
| `dark` | продуктовые презентации и демо TN Life |

Не сказано какую — бери `brand` и напиши в ответе, что взял её.

Посмотреть темы вживую: `node examples/themes/build.js` собирает по деке на
каждую тему, в каждой — все 28 макетов.

### 3. Собери материал

Прочитай всё, что дал пользователь: бриф, черновик презентации, таблицы с цифрами,
документы. `.pptx` читается через `markitdown`, остальное — обычным чтением.
Если черновик есть, он задаёт структуру и факты. **Цифры не выдумывай**: чего нет
в исходниках, того нет на слайде.

Если из брифа неясно что-то из списка — задай один блок вопросов и дождись ответа:

- кто в зале и какое решение от них нужно;
- сколько слайдов и сколько минут;
- есть ли скриншоты, фото, графики — или ставить плейсхолдеры;
- язык (по умолчанию русский).

Отвечать некому — выбери разумный вариант, напиши какой, и продолжай.

### 4. Составь план деки

Сначала нарратив, потом макеты. Типовая рамка:

```
титул → агенда → проблема в цифрах → решение → доказательства →
план → что нужно от аудитории → финал
```

Правила:

- **Один тезис на слайд.** Заголовок — утверждение («Переключение съедает 40 минут
  в день»), а не рубрика («Проблематика»).
- **Макеты не повторять подряд.** Два списка подряд — признак лени. Цифры идут
  в `metrics` или `chart`, сравнение — в `compare`, этапы — в `process`/`timeline`.
- **Схемы — по делу.** `flowchart`, `sequence`, `architecture`, `journey` ставятся
  там, где смысл в связях, а не ради «серьёзного вида». Одна-две схемы на деку.
- Разделитель `section` — перед каждым крупным блоком. `statement` — там, где нужен
  один сильный тезис на весь экран.

Выбор макета — по таблице в `templates/README.md`. Покажи план пользователю
одним списком «номер — макет — заголовок», если деке больше 12 слайдов.

### 5. Собери деку

Создай `build.js`. В начале подключи пролог, дальше — по слайду на сниппет:

```js
const TN = require('./templates/_prelude');   // поправь путь под своё расположение
const p = TN.newDeck({ title: 'Название деки', theme: 'brand' });
await TN.prepare();                           // фоновая графика темы, если она есть
// ... слайды: копируй сниппеты из templates/*.md и подставляй свой контент
await p.writeFile({ fileName: 'out.pptx' });
```

`templates/_prelude.js` — это не сборщик, а набор примитивов: холст, токены, обёртки
над pptxgenjs и вертикальная композиция (`place`, `rows`, `boxH`). Все сниппеты
написаны под него и совпадают по геометрии. Не переписывай координаты «на глаз» —
они выверены.

Высоты блоков считаются по контенту. Не растягивай карточку до колонтитула ради
заполненности: пустая нижняя треть внутри карточки — дефект, воздух вокруг
компактного блока — нет.

Цвета берутся токенами (`C.bg`, `C.ink`, `C.accent`), а не литералами: токен меняется
вместе с темой, а `'#e11b11'` в тёмной теме останется красным пятном.

Рабочий пример на 29 слайдов, покрывающий все макеты: `examples/tn-life-strategy/build.js`.
Он берёт макеты из `templates/*.md`, а содержит только контент деки — так превью
в документации не расходятся с шаблонами.
Так выглядит результат: `examples/tn-life-strategy/preview/`.

Если `require('pptxgenjs')` или `require('sharp')` падает — `npm install pptxgenjs sharp`.
Без `sharp` соберётся всё, кроме иконок и белого логотипа на красном фоне.

### 6. Проверь глазами

Обязательный шаг, не пропускать.

```bash
node build.js
soffice --headless --convert-to pdf out.pptx
pdftoppm -jpeg -r 110 out.pdf slide
```

Посмотри **каждый** слайд и пройди `rules/quality.md`. Типовые дефекты: текст вылез
за рамку, наложения, забытый плейсхолдер «вставьте 1000×650» там, где должна была быть
картинка. Правь `build.js` и пересобирай.

Если Inter не установлен в системе, рендер подставит другой шрифт и покажет переносы,
которых в PowerPoint не будет. Проверь `fc-list | grep -i inter`; без Inter превью
годится для проверки композиции, но не переносов.

### 7. Отдай результат

Положи `.pptx` туда, откуда пользователь его заберёт. В ответе — одной-двумя фразами:
сколько слайдов и какая логика. Отдельным списком: какие картинки вставить и какие
цифры подтвердить. `build.js` сохрани рядом — по нему пересобирают деку после правок.

```
  brand.md / division.md / digital.md / dark.md — описание каждой темы
  contrast.js              — проверка контраста тем по WCAG

  README.md                — каталог макетов: что когда применять
  _prelude.js              — примитивы, подключаются в начале сборки
  _themes.js               — значения токенов, шрифты и обложки тем
  _snippets.js             — загрузчик сниппетов из .md, им пользуются примеры
  opening.md               — title, section, statement, closing
  text.md                  — agenda, bullets, features, cards, quote, takeaways
  data.md                  — metrics, table, chart, dashboard
  flow.md                  — process, timeline, compare, milestones
  visual.md                — split, image, devices
  diagram.md               — flowchart, sequence, architecture, map, board, matrix, journey

  logo-*.png               — логотипы с прозрачностью
  tn-icons-sprite.svg      — спрайт, 326 иконок

examples/themes/           — образцы тем: по деке на тему, все макеты
```

## Чего не делать

- Не собирать слайды картинками и не конвертировать HTML в PPTX.
- Не редактировать XML внутри готового `.pptx`.
- Не изобретать цвета, кегли и отступы мимо `rules/brand.md`.
- Не смешивать темы в одной деке и не подменять шрифт темы вручную.
- Не выкладывать деку без просмотра отрендеренных слайдов.
